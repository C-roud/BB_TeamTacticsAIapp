
バスケットボール戦術記録・編集ツール (BB_TeamTactics)
バスケットボールの戦術における選手の動きを、直感的なUIで時系列データとして記録・編集し、CSVファイルとして出力できるWebアプリケーションです。

大学の研究におけるデータ収集を目的として、特別なソフトウェアなしで、コーチが持つ戦術イメージを手軽にデジタル化するために開発されました。



主な機能
直感的なUI: ドラッグ＆ドロップで選手を自由に配置できます。

タイムライン編集: 0.5秒ごとのキーフレーム方式で、時間を指定しながら各選手の配置を自由に編集・修正できます。

ボール保持者の指定: 選択した選手をワンタッチでボール保持者として設定できます。

CSVエクスポート: 作成した戦術データを、分析に利用しやすいCSV形式で出力します。

CSVインポート: 一度出力したCSVファイルを読み込み、編集を再開できます。

インストール不要: Webブラウザだけで動作し、PCやタブレットからURLにアクセスするだけで利用可能です。

使い方
1. 基本的な戦術の作成
選手の配置: コート上の選手（駒）をドラッグ＆ドロップで初期位置に配置します。

最初の局面を保存: タイムラインが Time: 0.0 s の状態で、この時間の配置を保存 ボタンを押します。これで最初のキーフレーム（動きの起点）が保存され、タイムライン上に青いマーカーが表示されます。

時間を進める: タイムラインの右側にある ▶ ボタンを押して、時間を 0.5 s に進めます。

次の動きを作成: 選手を0.5秒後の位置に動かします。

局面を保存: 再び この時間の配置を保存 ボタンを押し、0.5 s 時点の配置を保存します。

繰り返し: 3〜5を繰り返し、24秒後までの動きをパラパラ漫画のように作成していきます。

2. 便利な機能
ボール保持者の設定:

ボールを持たせたい選手をクリックして選択します（水色の枠が付きます）。

画面右下のステータス表示エリアにある ボール保持者にする ボタンを押します。

設定が終わったら、必ず この時間の配置を保存 ボタンを押して変更を記録してください。

戦術の確認と修正:

タイムライン上の灰色のバーや、青いマーカーをクリックすると、その時間の配置がコート上に再現されます。

修正したい時間の配置を再現し、選手を動かして この時間の配置を保存 を押せば、その時間のデータが上書き更新されます。

3. データの保存と読み込み
エクスポート (データ出力):

操作パネルの CSVエクスポート ボタンを押すと、作成した全てのキーフレームデータが tactics_YYYYMMDD_HHMMSS.csv というファイル名でダウンロードされます。

インポート (データ読込):

後日、編集を再開したい場合は、操作パネルの CSVインポート ボタンを押します。

以前エクスポートしたCSVファイルを選択すると、データが読み込まれ、タイムラインと選手の配置が復元されます。

# 戦術提案（AI）機能の追加

ボード上の赤駒（r1〜r5）の**初期配置**・**ボール保持者**・選手プロフィール（身長と10エリアのシュート率）・**ドライブ/パスの重視**から、
その チームに合ったセットオフェンスの案（上位3案）を生成し、そのままタイムラインに読み込んで再生できます。
計算はすべてブラウザ内で行うため、サーバー不要で **GitHub Pages にそのまま置いて動かせます**。

## 使い方
1. 最初の画面で選手プロフィールを入力（またはCSVをインポート）して「戦術ボードへ進む」。
2. 赤駒を初期配置に動かし、ボール保持者にしたい赤駒を選んで「ボール保持者にする」。
3. 画面下の「戦術提案（AI）」で、セットの長さ・ドライブ/パスの重視を選び「提案を生成」。
4. 気に入った案の「この案をボードに読み込んで再生」を押す。★は最終シュートの位置。
5. 読み込んだ案は通常のキーフレームなので、動かして修正したり、「戦術CSVエクスポート」で保存できる。

「エリア表示」ボタンで、10エリアの境界を確認できます（番号は `main.js` の `AREA_DEFINITIONS` と同じ）。
「右/左」は、リングに向かって攻める選手から見た右手側＝画面の上側としています。逆なら「詳細設定」の「左右を反転」を使ってください。

## ファイル構成
| ファイル | 役割 |
|---|---|
| `index.html` / `main.js` / `style.css` | 既存の戦術記録ツール（`main.js` は変更していません。`index.html` と `style.css` に提案パネルを追記） |
| `suggest.js` | 提案パネル（入力の読み取り・結果表示・ボードへの読み込み） |
| `engine.js` | 提案エンジン本体（研究用の Python 版 `chain_search.py` の JavaScript 移植版） |
| `macros_data.js` | **マクロ（基本戦術）のデータ。下記の手順で生成して置く** |
| `tools/export_web_data.py` | `macros_data.js` を生成するスクリプト（研究用の Python プロジェクトで実行） |

## macros_data.js の作り方（マクロを追加・変更したとき）
研究用プロジェクト（`setplay_ai`）で、マクロCSV（`data/macros/*.csv`）から生成します。
```
cd setplay_ai
python build_meta.py                                  # macro_meta.json を最新にする
python export_web_data.py --out macros_data.js        # このリポジトリの tools/export_web_data.py を setplay_ai にコピーして実行
```
できた `macros_data.js` を `index.html` と同じ場所に置いて、GitHub に push します。

## GitHub Pages で公開する
1. このフォルダの中身（`index.html`、`main.js`、`style.css`、`suggest.js`、`engine.js`、`macros_data.js`、`court.jpg`）をリポジトリの直下に置いて push。
2. GitHub の Settings → Pages → Source を「Deploy from a branch」、Branch を `main` / `(root)` にして Save。
3. 数分後に `https://<ユーザー名>.github.io/<リポジトリ名>/` で誰でも使えるようになります。

手元で試すだけなら `index.html` をダブルクリックで開けます（`python -m http.server` でも可）。

## 提案の考え方と限界（正直な注意）
- 期待得点 = （選手のエリア別シュート率）×（得点価値 2点/3点）×（守備者の接近による減衰）。**案どうしを比べるための指標**で、実戦の得点を予測するものではありません。
- シュート率は「フリー（守備なし）で測った値」として扱います（詳細設定で「試合での成功率」にも変更可）。
- 守備は、各攻撃選手にマンツーマンで付いていく簡易モデルです。
- 基本戦術（マクロ）15種を、初期配置に合わせて再配置・連結して案を作ります。マクロにない動きは出せません。

# 採点モード（試合の振り返り）

自分たちのオフェンスを、戦術ボード上で**赤（攻撃）と青（守備）の10駒**を使って記録し、「採点する」で振り返るモードです。
機械学習は使いません。計算はすべてブラウザ内で行うので、ノートPCでも、GitHub Pages 上でも動きます。
画面の「採点モード（振り返り）」タブで切り替えます。

## 使い方
1. 選手プロフィール（身長・10エリアのシュート率）を入力しておく（戦術提案モードと共通）。
2. 駒を動かして「この時間の配置を保存」を、動きの節目ごとに記録する（最初と最後の配置は必須。0.5秒刻み）。
3. ボールを持つ赤の駒を選んで「ボール保持者にする」を、パスのたびに記録する。**最後にシュートを打つ選手が、最後の配置でボールを持つ**ようにする。
4. 青の駒（守備）も、実際の守備の位置に動かして記録する。**守備者の位置が、シュートの難しさの計算に使われます。**
5. 「採点する」。途中の時点を採点したいときは、タイムラインをその時刻に合わせて「いまの時刻をシュート時点にする」。
6. 結果は「結果をコピー」でテキストとして保存できます。

## 採点の項目（1つの合計点は出しません。項目ごとの内訳です）
| 項目 | 内容 |
|---|---|
| 最終シュート | 打った選手・エリア・期待得点・開始直後に打つ場合との差・最寄りの守備者までの距離 |
| 気づいた点 | ルールに基づく自動コメント（根拠の数字つき） |
| 他の選択肢 | シュート時点で他の選手が同じ場面で受けていたら（簡易なパスコース判定つき） |
| 動きの内訳 | 関与した人数、パス・ドリブルの量、赤の駒どうしの距離（詰まりすぎ） |
| 近い基本戦術（目安） | 登録済みマクロのどれに近い動きか。各マクロを、あなたの駒の配置から始まる形に直し、実際の動きとの位置のずれで判定 |
| AI案との比較 | 同じ初期配置・ボール保持者・選手でのAI案の期待得点。AI案はボードに読み込んで見比べられる |

## 限界（正直な注意）
- 期待得点は「案どうしを比べるための指標」で、実戦の得点を予測するものではありません。シュート率は「フリーで測った値」として扱っています。
- 位置は、保存したキーフレームの間を直線で補間します。ボール保持者は、次のキーフレームまで直前のままとして扱います。
- 0.5秒刻みの記録なので、一瞬のスティールや守備の反応は見えません。
- 「近い基本戦術」は目安です。動きが小さいマクロは、静止と区別できないため対象外です。人の動きがマクロから大きくずれると、検出できません。
- 守備の位置は入力した人の判断に左右されます。

## 追加ファイル
`scoring.js`（採点の計算。画面に依存しない）、`score_ui.js`（採点モードの画面）。

# モード切り替え と 試合モード（スコアシート & チーム分析）

## モード切り替え
- 起動直後のトップ画面で「**練習モード**」「**試合モード**」を選びます。
  - 練習モード：従来どおり（選手プロフィール入力 → 戦術提案（AI）／採点モード／戦術ボード）。
  - 試合モード：プロフィール入力なしで開始。戦術ボード ＋ リアルタイム・スコアシート。
- 開始後は、画面上部の「モード」ボタンでいつでも切り替えられます（記録は消えません）。練習モードへ切り替えるときにプロフィールが未入力なら、セットアップ画面が開きます（「元のモードに戻る」で戻れます）。

## 試合モードの使い方
1. 「選手の番号」に背番号を入力する。
2. 各セルの **▲（＋1）／▼（－1）** で記録する。
   - 3P・2P・FT は「成功 / 試投」の2セル。**成功の▲** を押すと試投数も自動で＋1、**試投の▲** は失敗（ミス）の記録になります。▼ は取り消し（成功数 ≦ 試投数は常に保たれます）。
   - ORB・DRB に加え、TOV（ターンオーバー）も記録します（TOV%・ポゼッション・USG%の計算に必要なため）。
3. 最下部の「**相手チーム**」行に、相手の合計（3P・2P・FT・ORB・DRB・TOV）を入力する。ORB%・DRB%・DRtg・Net Rtg・Four Factors の比較に必要です（未入力でも自チームの指標は出ます）。
4. 数値を変えるたびに、選手ごとの指標・チーム合計・ダッシュボードが即時に再計算されます。入力は自動保存され、ブラウザを閉じても残ります。
5. 「**CSVエクスポート**」で、スコアシート・チーム分析を `scoresheet_YYYYMMDD_HHMMSS.csv`（Excel対応のUTF-8 BOM付き）として保存できます。

## 計算式（`analytics.js` に実装。画面に依存しないので、式の確認・変更はここだけ）
| 指標 | 式 |
|---|---|
| FGM / FGA / PTS | FGM=3PM+2PM、FGA=3PA+2PA、PTS=3×3PM+2×2PM+FTM |
| **eFG%** | (FGM + 0.5×3PM) ÷ FGA |
| **TS%** | PTS ÷ (2×(FGA + 0.44×FTA)) |
| **TOV%** | TOV ÷ (FGA + 0.44×FTA + TOV) |
| **ORB%** | ORB ÷ (ORB + 相手DRB)　／　DRB% = DRB ÷ (DRB + 相手ORB) |
| **FT Rate** | FTA ÷ FGA |
| ポゼッション(推計) | FGA − ORB + TOV + 0.44×FTA（相手の記録があれば自・相手の平均） |
| ORtg / DRtg / Net | 100×PTS÷Poss ／ 100×失点÷Poss ／ ORtg−DRtg |
| PPP | PTS ÷ Poss |
| **USG%（簡易）** | 選手の(FGA + 0.44×FTA + TOV) ÷ チーム合計 ← 出場時間を使わない簡易版（全選手の合計が100%） |
| 個人効率 | 100×PTS ÷ (FGA + 0.44×FTA + TOV)（ボールを使った100回あたりの得点） |

Four Factors の重み（シュート40・TO25・リバウンド20・FT15）は D. Oliver の目安です。「◎優勢／▲劣勢」は自チームと相手の差で判定します（TOV%のみ低いほうが優勢）。選手のTS%は、チーム平均より2pt以上高いと緑、10pt以上低いと赤で表示します（使用ポゼッション3回未満は色なし）。

### 限界（正直な注意）
- ポゼッションは推計値です。短い時間・少ない試投数では数字が大きく振れます（ポゼッション20回未満のときは画面に注意を表示します）。
- USG%は出場時間を考慮しない簡易版です。出場時間が選手ごとに大きく違う場合は、実際のUSG%と差が出ます。
- アシスト・スティール・ブロック・ファウルは記録しないため、PER などの総合指標は出しません。

## スマホ・タブレットでの表示
- `responsive.js` が、画面幅に合わせてコートを縮小表示します（駒の座標は常に1000px基準のままなので、保存データ・AI提案・採点は端末が違っても同じ値です）。
- 縮小すると駒が小さくなるため、縮小率に応じて駒を少し大きく表示します。**駒を細かく動かすときは、スマホを横向きにするのがおすすめです**（縦向きは、コートの幅が約 0.37 倍になります）。
- 試合モードのスコアシートは、横にスクロールしても「選手の番号」が左に残ります。
- `main.js` のドラッグ処理は、縮小率を考慮した座標計算に変更しました（PC等倍では従来と同じ結果です）。
